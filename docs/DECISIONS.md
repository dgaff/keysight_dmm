# Decisions

Newest last. Each entry: what was decided and why.

## Product (agreed with Doug, 2026-11-11)

- **"On-meter logging" = timer-paced sampling into reading memory**
  (`SAMP:SOUR TIM`, `SAMP:TIM`, `SAMP:COUN`, `TRIG:*`, drained with `R?`/`DATA:REM?`
  or saved with `MMEM:STOR:DATA`). The meter's own Data Log mode is front-panel only
  (manual p. 81, p. 177) with no documented SCPI. Look for an undocumented way to drive
  it in the experimental phase.
- **Capability-driven across the Truevolt family, tested only on the 34470A.**
- **macOS 27 only, local build**, no notarization or distribution.
- **Bench limits:** ≤ 10 V, ≤ 100 mA.
- UX departures from BenchVue: readout and chart visible together; settings panels
  mirror the front-panel soft keys with help popovers showing the SCPI sent;
  macOS notification/sound instead of e-mail/batch-file limit actions; screen capture
  without annotation tools (Preview Markup covers that).

## Architecture

- **SwiftPM package, no Xcode project.** `swift build`/`swift test` work headless and
  are easy for sub-agents. The app will be an executable target bundled into a `.app`
  by a script (needs an Info.plist with `NSLocalNetworkUsageDescription` and
  `NSBonjourServices` for Bonjour browsing).
- **No third-party dependencies**, so builds never need the network.
- **Transport: raw SCPI socket, TCP 5025**, via Network.framework. Simple and
  sufficient. HiSLIP only if we come to need device clear or service requests.
- **Receive path is a lock-protected buffer with timer-based timeouts** (`ByteInbox`),
  not task-group racing: a pending `NWConnection.receive` cannot be cancelled, so a
  racing design would hang on timeout.
- **Timeout recovery:** after a timed-out query the session discards buffered bytes
  before the next command. The meter drops an unread response when a new command
  arrives and queues -410, so stale data cannot be mistaken for the next answer.
  An unknown query header produces no response at all (plus -113), so it costs a full
  timeout; callers probing optional features should use a short timeout.
- **Error checking:** `SCPISession.set` sends the command and then drains `SYST:ERR?`.
  Two round trips per setting change is fine at human speeds.
- **Commands use upper-case short forms** (`VOLT:NPLC`), which is also what
  `SimulatedMeter` matches on.
- **Display formatting is locale-independent** ("." decimal separator always), matching
  the instrument and keeping exports unambiguous.
- **The manual PDF and its extracted text are gitignored** (Keysight copyright);
  `scripts/extract_manual.sh` regenerates the text.

## Observed on the real meter (fw A.03.03)

- `*OPT?` → `0,0,0,0,0`; `SYST:LIC:CAT?` → `""`. No MEM licence: reading memory is
  50,000 (`SAMP:COUN:PRET? MAX` → 49999). Pre-trigger is accepted, so the digitizer
  feature set is present (included in current firmware).
- `FORM:DATA?` → `ASC,9`. Readings come back as `+1.00000000E-01`.
- `SAMP:COUN? MAX` → 1,000,000,000. `SYST:LFR?` → 60.
- `SYSTem:HELP?` is documented and should list every command the firmware accepts:
  the starting point for the undocumented-command hunt.
- Bonjour: the meter advertises `_scpi-raw`, `_lxi`, `_hislip`, `_vxi-11`,
  `_scpi-telnet`; TXT keys `Manufacturer`, `Model`, `SerialNumber`, `FirmwareVersion`.
- All 13 function profiles were read back from the real meter (`dmmprobe settings
  <host>`): every header answers, including `? MIN`/`? MAX` on `CURR:TERM`.
  Corrections from that run:
  - The top AC voltage range (also frequency/period input range) reads back as 1000,
    not 750, although the panel calls it 750 V. `VOLT:AC:RANG 750` is accepted and
    selects it. The step list uses 1000 so values round-trip.
  - `PER:TIM:AUTO?` is not accepted; `FREQ:TIM:AUTO` is shared by both functions.
  - `CURR:RANG? MAX` is 3 A (10 A is selected with `CURR:TERM 10`).
  - Temperature null limits are ±1e15.
- `DATA:LAST?` appends a unit string (`+3.74780121E-03  VDC`); `DATA2?` answers
  9.91E37 when no secondary measurement is configured.
- Live readings: a `READ?` loop gives about 3 readings/s at 10 PLC with auto zero on,
  as expected (2 × 167 ms per reading).
- The command catalogue (`scpi_commands.json`) was generated by a sub-agent from the
  manual text. It marks capacitance as 34465A/70A-only, which is doubtful (the manual
  is inconsistent); irrelevant on the 34470A, revisit if another model is ever used.
